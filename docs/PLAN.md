# 쉬운 음악 만들기 — 기획 · 설계 문서

> 유튜브 링크로 노래를 불러와 **잘라내기 · 빠르기 · 이어 붙이기**를 하고 mp3로 저장하는 PC 웹 서비스.
> 주 사용자: **디지털에 익숙하지 않은 계층** → 쉬운 UI/UX가 최우선.

## 1. 요구사항

| 구분 | 내용 |
|---|---|
| 입력 | 유튜브 링크를 넣으면 노래를 **불러오기** (바로 다운로드 X) |
| 편집 | 서비스 안에서 편집 — **속도 조절, 자르기, 여러 곡 이어 붙이기** |
| 출력 | 편집 결과를 mp3로 저장 |
| 플랫폼 | **PC 웹** (모바일 아님) |
| 사용자 | 디지털 취약 계층 → 쉬운 UI/UX |
| 추가 | 곡별 편집 + **모든 노래에 한 번에 적용** 기능 |

추천 부가 기능 (기획 중 제안, 채택):

| 기능 | 설명 |
|---|---|
| 노래 사이 부드럽게 잇기 | 크로스페이드 (기본 2초) |
| 소리 크기 고르게 맞추기 | 곡마다 다른 음량을 정규화 (loudnorm) |
| 목소리 높낮이 유지 | 빠르기를 바꿔도 음정 유지 (기본 ON) |

## 2. 사용자 흐름

| 단계 | 화면 | 내부 동작 |
|---|---|---|
| ① 주소 넣기 | URL 입력 + [붙여넣기] + [노래 불러오기] | URL 검사 (youtube.com / youtu.be만) |
| ② 불러오는 중 | 썸네일, 제목, 진행률, 남은 시간 | yt-dlp로 오디오 추출 → 변환 → 파형 생성 |
| ③ 편집 홈 | 노래 카드 목록 | 브라우저에서 미리듣기 |
| ④ 한 곡 잘라내기 | 카드의 [잘라내기] | 편집 JSON만 변경 |
| ⑤ 한 곡 빠르기 | 카드의 [빠르기] | 편집 JSON만 변경 |
| ⑥ 모든 노래 빠르기 | 편집 홈의 [모든 노래 빠르기 바꾸기] | 편집 JSON만 변경 |
| ⑦ 저장 완료 | [내 컴퓨터에 저장하기] | 서버에서 ffmpeg 최종 렌더링 → mp3 |

```
① 주소 넣기 → ② 자동 불러오기 → ③ 편집 홈(노래 목록)
                                   ├─ 카드 [잘라내기] → ④ → [완료] → ③
                                   ├─ 카드 [빠르기]   → ⑤ → [완료] → ③
                                   ├─ [모든 노래 빠르기] → ⑥ → [적용] → ③
                                   ├─ [노래 하나 더 붙이기] → 목록에 추가
                                   └─ [다 됐어요, 저장하기] → ⑦ 저장 완료
```

## 3. 편집 기능 상세

| 기능 | 사용자 조작 | 미리듣기 (브라우저) | 최종 출력 (서버 ffmpeg) |
|---|---|---|---|
| 잘라내기 | [−5초] [+5초] 버튼 (파형 드래그도 가능) | `<audio>` start~end 구간 재생 | `atrim` |
| 빠르기 | 느리게 0.75 / 보통 1.0 / 빠르게 1.25 + [−][+] 세밀 조절 | `playbackRate` + `preservesPitch` | `atempo` (음정 유지) / `asetrate` (음정 변함) |
| 이어 붙이기 | 카드 [위로] [아래로] [빼기], [노래 하나 더 붙이기] | 순서대로 재생 | `concat` |
| 부드럽게 잇기 | 체크박스 | 볼륨 페이드 | `acrossfade` |
| 소리 크기 맞추기 | 체크박스 | – | `loudnorm` |

**핵심 설계 — 비파괴 편집**: 편집 중에는 원본 파일을 건드리지 않고 편집 내용을 JSON으로만 저장 → 내보낼 때 한 번에 렌더링.
→ 되돌리기가 쉽고, 서버 부하가 적고, 버튼을 누르는 즉시 반영된다.

## 6. 적용 범위 규칙 (한 곡 vs 전체)

### 배경 — 처음 설계의 문제

초기 와이어프레임은 편집 화면을 [잘라내기][빠르기][이어 붙이기] **탭**으로 나눴는데, 여러 곡을 이어 붙인 뒤에는:

| 문제 | 상황 |
|---|---|
| 어떤 노래에 적용되는지 모름 | 잘라내기 탭에 한 곡만 보이고 다른 곡을 고를 방법이 없음 |
| 전체 적용인지 모름 | 빠르기를 바꾸면 1번만인지 전체인지 알 수 없음 |
| [적용하기] 안 누르면? | 탭을 옮기면 변경이 사라지는지 알 수 없음 |

### 검토한 방안

| 방안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 탭 + 노래 선택 | 탭 위에 [1번][2번] 선택 | 화면 재사용 | 선택 단계가 늘어 헷갈림 |
| B. 결과 전체에 적용 | 이어 붙인 결과를 한 곡처럼 | 단순해 보임 | 곡 경계를 넘는 자르기가 어려움 |
| **C. 노래 카드 중심 ✅** | 편집 홈 = 노래 목록, 카드마다 [잘라내기][빠르기] | "이 노래를 고친다"가 명확 | 화면 구조 변경 필요 |

### 확정 규칙

| 항목 | 규칙 |
|---|---|
| 잘라내기 | **항상 한 곡씩** |
| 빠르기 | 기본 한 곡, **[모든 노래]** 선택 가능 |
| 충돌 | 모든 노래 빠르기를 정하면 곡별 값을 **덮어씀** → 화면에서 미리 경고 |
| 부드럽게 잇기 · 소리 크기 맞추기 | 전체 설정 |
| 적용 시점 | 즉시 반영 + "바뀌었어요 [되돌리기]" |
| 결과 확인 | 카드에 바뀐 길이 · 빠르기 표시 (예: `3:12 · 1.25배`) |
| 전체 자르기 | **넣지 않음** — 첫 곡 앞 / 마지막 곡 뒤 자르기와 결과가 같아 버튼만 늘어남 |
| 내부 처리 순서 | 자르기 → 빠르기 → 소리 크기 → 잇기 (자르기 시간은 원곡 기준 유지) |

## 7. 풀스택 아키텍처

원칙: **편집은 브라우저에서 미리듣기만, 실제 파일 처리는 내보낼 때 서버(ffmpeg)에서 한 번만.**

```
[브라우저: React]
   │  ① 주소 제출        ④ 편집 JSON 보내서 내보내기
   ▼                     ▼
[API 서버: FastAPI] ──작업 등록──▶ [Redis] ──▶ [작업자: Celery]
   │                                            ├ yt-dlp  (오디오 추출)
   │                                            └ ffmpeg  (파형 생성, 최종 렌더링)
   ▼
[파일 저장소: 로컬 → 나중에 GCS/S3]  ※ 24시간 뒤 자동 삭제
```

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | React + TypeScript (Vite) | 익숙한 스택 |
| 상태 관리 | Zustand | 편집 JSON + 되돌리기 기록만 관리 |
| 파형 | wavesurfer.js | 서버가 만든 peaks를 그리기만 |
| API | FastAPI | 비동기, 자동 문서화 |
| 작업 큐 | Celery + Redis | 추출 · 렌더링이 수십 초 소요 |
| 처리 도구 | yt-dlp, ffmpeg | 표준 도구 |
| DB | MVP는 Redis만, 이후 Postgres | 로그인이 없으면 DB 거의 불필요 |
| 배포 | Docker Compose → Cloud Run | GCP 이전 용이 |

화면별 처리:

| 화면 | 프론트 | 서버 |
|---|---|---|
| ① 주소 넣기 | 주소 검사 | `POST /tracks` 작업 등록 |
| ② 불러오는 중 | 1초마다 진행률 조회 | yt-dlp 추출 → 44.1kHz 스테레오 변환 → 파형 JSON |
| ③ 편집 홈 | 카드 목록 = 편집 JSON `tracks` 배열 | – |
| ④ 잘라내기 | `<audio>` 구간 재생 | – |
| ⑤⑥ 빠르기 | `playbackRate` + `preservesPitch` | – |
| ⑦ 저장 | 편집 JSON 전송 | ffmpeg 렌더링 → mp3 링크 |

## 9. 편집 데이터 (Edit JSON)

```json
{
  "tracks": [
    { "sourceId": "abc123", "start": 12.5, "end": 200.0, "speed": 1.0,  "keepPitch": true },
    { "sourceId": "def456", "start": 0,    "end": 240.0, "speed": 1.25, "keepPitch": true }
  ],
  "crossfade": 2,
  "normalize": true,
  "format": "mp3"
}
```

- 배열 순서 = 이어 붙이는 순서
- `start` / `end`는 **원곡 기준** 초
- "모든 노래 빠르기"는 모든 `tracks[].speed`를 같은 값으로 덮어쓰기
- 되돌리기: 변경마다 이전 JSON을 history 스택에 저장

## 10. ffmpeg 렌더링

```python
def build_filter(tracks, crossfade: float, normalize: bool) -> str:
    parts = []
    for i, t in enumerate(tracks):
        f = [f"atrim=start={t.start}:end={t.end}", "asetpts=PTS-STARTPTS"]
        if t.speed != 1.0:
            f.append(f"atempo={t.speed}" if t.keep_pitch
                     else f"asetrate={44100*t.speed},aresample=44100")
        if normalize:
            f.append("loudnorm=I=-16:TP=-1.5:LRA=11")
        parts.append(f"[{i}:a]{','.join(f)}[a{i}]")

    # 이어 붙이기
    if len(tracks) == 1:
        parts.append("[a0]anull[out]")
    elif crossfade > 0:
        prev = "a0"
        for i in range(1, len(tracks)):
            out = "out" if i == len(tracks) - 1 else f"x{i}"
            parts.append(f"[{prev}][a{i}]acrossfade=d={crossfade}[{out}]")
            prev = out
    else:
        ins = "".join(f"[a{i}]" for i in range(len(tracks)))
        parts.append(f"{ins}concat=n={len(tracks)}:v=0:a=1[out]")
    return ";".join(parts)
```

- 처리 순서: 자르기 → 빠르기 → 소리 크기 → 잇기
- 소리 크기는 실제로는 `loudnorm` 한 번 처리 대신 **곡별 측정(ebur128) → 고정 음량(`volume`)** 2단계로 한다 (결정 44, 20분 × 20곡에서 loudnorm은 911초 → 176초)
- 추출 단계에서 모든 소스를 44.1kHz 스테레오로 통일해 둘 것
- 크로스페이드 길이가 곡 길이보다 길지 않은지 검증 필요

## 13. 개발 순서 (MVP)

| 단계 | 범위 | 화면 |

| 1 | 주소 → 추출 → mp3 다운로드 | ① ② ⑦ |
